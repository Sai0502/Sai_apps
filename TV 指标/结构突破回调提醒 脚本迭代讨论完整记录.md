            pointBar := array.get(bars, n - 2)
            pointTime := array.get(times, n - 2)

## 2. 功能梳理（AI 逐模块分析）

### 2.1 总体概览

这是一个基于 **Smart Money Concepts (SMC)** 理论的 TradingView 指标，核心功能是：

> **识别多层级市场结构（Swing High/Low），检测结构突破（BOS）和市场结构转变（MSS），在突破后的回踩起点发出提醒，可选放量确认。**

- **版本**：Pine Script v6
- **类型**：`indicator`（叠加在主图上）
- **名称**：`放量MSS_提醒`
- **最大线数**：500 条线，500 个标签

### 2.2 输入参数

**提醒层级选择：**
- `alertLevel`：Level 1 STH/STL / Level 2 ITH/ITL / Level 1 + Level 2

**Level 1（STH/STL — 短期高低点）：**
- `showLevel1Points` (true) / `level1Color` (gray透明15) / `showLevel1BOS` (true) / `level1BreakColor` (gray透明20) / `level1LineWidth` (1)

**Level 2（ITH/ITL — 中期高低点）：**
- `showLevel2Points` (true) / `level2Color` (yellow) / `showLevel2BOS` (true) / `level2BreakColor` (lime) / `level2LineWidth` (2)

**放量模式：**
- `volumeMode` (false) / `volumeLength` (20, 硬编码) / `volumeMultiplier` (1.25, 硬编码) / `volumeBreakColor` (black) / `volumeLineWidth` (3) / `volumeConfirmMode` (3种) / `volumeConfirmBars` (3) / K线颜色染色（放量阳线/阴线、普通阳线/阴线）

### 2.3 核心数据结构

**有效 K 线数组（Mother Bar 机制）：**
- `effectiveHighs` / `effectiveLows` / `effectiveBars` / `effectiveTimes`：只记录突破母K高低点的K线

**STH/STL 序列（Level 1）：**
- `sthValues` / `sthBars` / `sthTimes` / `stlValues` / `stlBars` / `stlTimes`

**活动状态变量：**
- Level 1: `activeSTH` / `activeSTL` + `Broken` + `IsL2` 标记
- Level 2: `activeITH` / `activeITL` + `Broken` 标记
- 最高有效高低点: `highestValidHigh` / `lowestValidLow` + `Broken` + 对应 bar/time/line/time

**偏向（Bias）状态：**
- `biasL1` / `biasL2`：1=多, -1=空, 0=初始

**待提醒状态（Pending Alert）：**
- L1/L2 各一套：`pendingActive` / `pendingDirection` / `pendingWasMSS` / `pendingBreakClose` / `pendingBreakLevel` / `pendingBreakBar`

**放量等待状态：**
- `volumeWaitActive` / `volumeWaitDirection` / `volumeWaitLevel` / `volumeWaitWasMSS` / `volumeWaitBreakClose` / `volumeWaitBreakLevel` / `volumeWaitBreakBar` / `volumeWaitExpiresBar` / `volumeWaitLine`

**去重状态：**
- L1/L2 各一套：`lastAlertDirection` / `lastAlertBreakLevel` / `lastAlertBreakClose`

### 2.4 核心逻辑流程

#### 有效 K 线（Effective Bar / Mother Bar）机制
不是每根 K 线都参与结构判断，只有"突破母K高低点"的 K 线才算有效，过滤震荡区间噪音。

#### Swing Point 识别（3 根有效 K 确认法）
- **STH**：中间根高点 > 左根高点 且 > 右根高点
- **STL**：中间根低点 < 左根低点 且 < 右根低点

#### Level 2（ITH/ITL）确认
- **ITH**：从 `sthValues` 数列中取最近 3 个 STH，中间 STH > 左 STH 且 > 右 STH → 中间 STH 升级为 ITH
- **ITL**：从 `stlValues` 数列中取最近 3 个 STL，中间 STL < 左 STL 且 < 右 STL → 中间 STL 升级为 ITL
- **层级关系**：ITH/ITL 是"STH/STL 的 Swing"，即更高层级的结构点

#### 最高有效高低点更新逻辑
当新 STH 确认时：
1. 如果 `activeSTH >= activeITH` → STH 直接作为最高有效高点（L1 升格为 L2 权重）
2. 如果 ITH 确认且 `activeSTH >= activeITH` → STH 为最高有效高点
3. 否则 → ITH 自身作为最高有效高点

#### 实时高低点更新（Sweep 修正）
如果 high > activeSTH 但 close <= activeSTH → 认为是扫损（sweep），更新 activeSTH = high（抬高结构点位置）。避免假突破触发提醒。

#### 结构突破检测
- **BOS**：突破方向与当前偏向一致（`bias != 反方向`）
- **MSS**：突破方向与当前偏向相反（`bias == 反方向 或 bias == 0`）
- **优先级**：L2 突破优先于 L1

#### 突破后处理流程（以 bullBreakL1 为例）
1. 标记 activeSTHBroken = true
2. 更新 biasL1 = 1
3. 画突破线
4. 清除反方向的 pendingL1
5. 判断 shouldAlert（提醒层级匹配 + 放量模式检查）
6. 设置 pending 状态（等待回踩确认才发提醒）
7. 如果不 shouldAlert 且未放量 → 进入 volumeWait 状态

#### 放量确认机制
- **放量定义**：`volume > SMA(volume, 20) * 1.25`
- **三种确认模式**：突破K必须放量 / 允许下一根K补放量确认 / 允许N根内补放量确认

#### 回踩提醒触发（Pullback Alert）
触发条件：
1. pending active
2. 方向匹配
3. **新 Swing Point 形成**（newSTH 或 newSTL）
4. 当前 bar > 突破 bar
5. 不是重复提醒（`f_same_alert` 去重：方向相同 + 突破位差值 ≤ mintick*0.5 + 收盘价差值 ≤ mintick*0.5）
6. L1 提醒不被 L2 提醒覆盖

#### 提醒消息格式
```
Bullish MSS [Level 2 ITH/ITL] pullback started on BTCUSDT.
Break level: 50000.0. Break close: 50100.0. Current close: 50200.0.
Timeframe: 1D.
```

### 2.5 辅助函数

| 函数 | 功能 |
|------|------|
| `f_confirm_low` | 从低点序列确认 swing low（3 点法） |
| `f_confirm_high` | 从高点序列确认 swing high（3 点法） |
| `f_mark` | 在图上绘制标签标记 |

## 3. 改进建议（17 项，按优先级排列）

### 高优先级（逻辑/正确性问题）

**1. `volumeLength` 和 `volumeMultiplier` 硬编码，应改为 input**
用户无法在设置面板调整这两个核心参数，只能改代码。

**2. L1/L2 优先级排除逻辑可能漏信号**
`bullBreakL1` 要求 `not bullBreakL2`，即 L2 突破时 L1 被完全忽略。L1 突破和 L2 突破可能发生在同一根 K 上，此时只触发 L2 提醒，L1 提醒丢失。

**3. `breakLine` 是 `var` 但每根 K 都可能被覆盖**
`breakLine` 用 `var` 声明但每根突破 K 都会重新赋值，逻辑上不够干净。建议去掉 `var`，改为局部变量。

**4. 回踩提醒触发条件过于严格**
回踩提醒要求 `newSTH`（或 `newSTL`），即必须形成新的反向 Swing Point。如果价格突破后快速拉升不回踩，提醒永远不会触发。

**5. `volumeWaitLine` 可能引用已被覆盖的 line 对象**
如果 `showLevel1BOS`/`showLevel2BOS` 为 false，`breakLine` 为 `na`，放量确认后 `line.set_color` 会报错或无效。

### 中优先级（功能增强）

**6. 缺少 Order Block（订单块）标记**
**7. 缺少 FVG（Fair Value Gap / 公允价值缺口）检测**
**8. 缺少流动性池（Liquidity Pool）标记**
**9. 缺少偏向状态可视化**（`biasL1` / `biasL2` 没有在图上显示）
**10. 缺少多时间周期（MTF）支持**
**11. 提醒消息缺少关键信息**（bias 状态、成交量信息、K线距离、目标位）
**12. 没有提供策略回测接口**

### 低优先级（代码质量/体验）

**13. 数组无上限管理，长周期运行可能内存溢出**（只 push 不 pop）
**14. 函数复用不足，L1/L2 突破处理逻辑重复**（四段代码结构几乎完全相同）
**15. 放量 K 线颜色与 TradingView 默认配色冲突**
**16. 缺少调试/日志输出**
**17. `max_lines_count=500` 在高密度突破场景下可能不够**

## 8. 当前待讨论：ITH/ITL 定义问题

### 问题描述

用户在 TradingView 图表上发现两个问题（通过截图验证）：

1. **ITH 点被突破之后，再次回调产生的新的高点应该是新的 ITH 才对，现在却被标记为 STH**
2. **两个 ITH 之间的那个低点应该是 ITL，但是现在被标记为 STL**

用户认为 STH 的定义没问题，但 ITH 的定义需要重新审视。最重要的是 ITH 和 ITL。

### 当前 ITH/ITL 的定义（代码逻辑）

```pine
// ITH：从 STH 序列中取最近 3 个，中间最高
[confirmedITH, ithPrice, ithBar, ithTime] = f_confirm_high(sthValues, sthBars, sthTimes)
if confirmedITH
    activeITH := ithPrice
    ...

// ITL：从 STL 序列中取最近 3 个，中间最低
[confirmedITL, itlPrice, itlBar, itlTime] = f_confirm_low(stlValues, stlBars, stlTimes)
if confirmedITL
    activeITL := itlPrice
    ...
```

简单说：**ITH = 3 个 STH 中的 Swing High；ITL = 3 个 STL 中的 Swing Low。**

这是经典的分型结构——更高层级的分型需要下一层级的 3 个分型来确认。

### 为什么会出问题

当前逻辑中，**每次突破发生后，activeITH 会被标记为 broken，但脚本不会自动把突破后的新高点提升为 ITH**。新高点的确认仍然要依赖"3 个 STH 形成新的分型"这个规则。

但在实际走势中：
```
   ITH (old)          ← 被突破
     ↓ 突破
    pullback
     ↓
   new ITH            ← 回调后产生的新高，应该直接是 ITH
```

这个新高点在突破后一旦形成，**从结构意义上讲它就是新的 ITH**，因为它已经突破了前一个 ITH，理应升级为 ITH 级别。

### 核心问题

当前脚本的 ITH 确认是**纯分型的、滞后的**：
- 必须等 3 个 STH 出现才能确认 ITH
- 没有考虑"结构突破后的级别继承"

用户想要的 ITH 定义是**结构化的、动态的**：
- 一旦价格突破前 ITH，那么后续回调产生的新高点就是新的 ITH
- 两个 ITH 之间的低点自动升级为 ITL

### AI 提出的重新定义方案

#### ITH 新定义

**一个 STH 成为 ITH，当且仅当满足以下任一条件：**

1. **分型确认**（当前逻辑）：当前 STH 高于前后各一个 STH
2. **结构继承**（新增）：当前 STH 突破了前一个 activeITH，且突破后 bias 转为多头

#### ITL 新定义

**一个 STL 成为 ITL，当且仅当满足以下任一条件：**

1. **分型确认**（当前逻辑）：当前 STL 低于前后各一个 STL
2. **结构继承**（新增）：当前 STL 跌破了前一个 activeITL，且突破后 bias 转为空头
3. **夹逼升级**（新增）：在两个相邻 ITH 之间形成的最低点（即趋势段中的回调低点）
